# Eric Mingle 个人Demo脱敏展示

## 项目定位

这不是一个“项目压缩包”，而是一个面向人类读者和 AI 读者的对外展示项目。

它的核心用途只有一个：

用两个互补的小项目，支撑对以下问题的判断：

1. 是否具备 AI 产品经理需要的产品判断与技术路径选择能力
2. 是否具备把想法推进成 Demo、再推进成可复用资产的能力
3. 是否能从原始工作材料中看出真实的工作方式，而不是只看到整理后的结果

## 项目结构

本项目由三层组成：

1. 大项目入口层：说明为什么是这两个项目，以及应该怎么读
2. 两个小项目交付层：分别承载不同类型的能力证据
3. 证据层：包括项目文档、源码、复盘和长文本上下文

## 为什么是这两个项目

这两个项目不是重复展示，而是分工互补：

1. `Solution Diagram Workflow`
作用：更适合展示探索路径、决策拐点、Skill 化收口，以及原始长文本工作材料。

2. `Excel Intelligent Translation`
作用：更适合展示 Demo 完整度、稳定性、成本意识和产品化推进思路。

## 怎么开始读

入口规则：

1. 先读本文件，理解整个包为什么存在。
2. 再读 `selected_projects/README.md`，理解两个小项目的分工。
3. 进入每个小项目前，必须先读该小项目自己的 `README.md`。
4. 不建议一开始直接进入源码、转录文件或零散上下文文件。

## 人类和 AI 的侧重点区别

### 人类读者

更适合基于单一文件或短文本，先完成这些偏经验、偏主观的第一轮判断：

1. 产品需求分析是否清楚
2. 技术路径选择是否合理
3. 是否体现出足够的经验与取舍能力
4. 是否与 AI 产品经理岗位要求匹配

### AI 读者

更适合基于多文件和长上下文，完成这些更依赖证据整合的分析：

1. 多文件项目架构分析
2. 长对话文本总结
3. 求职者画像梳理
4. 基于长上下文的较客观能力归纳

## 两个小项目分别更适合看什么

### Solution Diagram Workflow

优先看它，如果你要分析：

1. 探索路径和决策拐点
2. Skill 化收口能力
3. 原始长文本工作材料
4. 更真实的推进方式

### Excel Intelligent Translation

优先看它，如果你要分析：

1. 已完成 Demo 的完整度
2. 稳定性与成本意识
3. 产品化推进思路
4. 架构演进与复盘能力

## 边界

这个项目的引导文件只定义“如何阅读和分析这些项目”，不直接替读者评价作者本人。

原始长文本上下文主要集中在 `Solution Diagram Workflow` 的 `transcripts/` 中；它们既是项目过程证据，也是分析作者一手工作材料的入口。

`Excel Intelligent Translation` 不承担同等级的原始长文本证据任务，它更适合作为完整度、稳定性和产品化能力的证据项目。
