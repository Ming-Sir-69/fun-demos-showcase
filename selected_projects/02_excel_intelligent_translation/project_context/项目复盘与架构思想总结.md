# 项目复盘与架构思想总结 (Project Retrospective Analysis)

## 1. 项目中遭遇的核心问题类型

在《Excel Intelligent Translation》引擎的开发与重构过程中，我们经历了从“跑不通”到“能跑”，再到“极速且完美”的蜕变。期间遇到的问题主要分为以下四大类：

### 1.1 自动化对“格式原貌”的破坏 (Formatting Destruction)
- **现象**：初期为了保证双语换行能够被完整显示，代码引入了全局的 AppleScript `autofit row`。结果导致用户在 Excel 模板中精心调整的特定长宽比被彻底打乱，版面拥挤丑陋。
- **本质**：自动化脚本的“侵入性”越权，试图用简单的代码逻辑代替用户的审美和专业排版。

### 1.2 模型并发假死与限流 (API Timeout & Rate Limits)
- **现象**：
  1. 使用本地 `gpt-oss` 时，多线程并发导致长文本处理时常挂起假死（Timeout）。
  2. 切换至国内 Moonshot Kimi API 后，瞬间触发 429 Rate Limit（限制 20 RPM），满屏报错且进度停滞。
  3. Kimi 报错 400 Invalid Temperature。
- **本质**：对不同厂商大模型 API 的协议差异（如参数支持、并发阈值）估计不足；没有在底层建设“指数退避/固定退避”等护城河机制。

### 1.3 逻辑切分过碎导致的语义割裂 (Micro-chunking Context Loss)
- **现象**：遇到长文本容易漏翻，于是引入了基于“句号、分号”的标点级切片。结果导致切片过于破碎（甚至只有 2 个字）。
- **本质**：破坏了大模型进行翻译时最依赖的“上下文语境 (Context)”，导致模型无法判断该词在工业语境中的含义。

### 1.4 愚蠢的“过度防呆” (Over-protection)
- **现象**：部分非常短的工业参数（如 `AA40` 的间隙要求，`AM91` 的量具要求）被系统强行跳过，导致最终生成的文件“半中半英”。
- **本质**：代码底层过度设计了防御机制（如 `if len < 2 or not isalpha()`），不信任上游分类器的结果，也不信任大模型的语言判别力。

## 2. 铭哥（用户）的指导方式

在陷入技术泥潭时，铭哥的指导风格呈现出极强的“敏捷开发”和“直指痛点”的特质：

1. **敏捷的“断电测试”与“范围缩减”**：
   - *“诊断各个流程，进行断电测试，减小测试区域减少等待，再次测试。”*
   - 不纠结于全篇死锁，而是果断切出前 20 行，快速跑通闭环，验证核心逻辑的可行性。这是典型的 MVP (Minimum Viable Product) 验证思维。
2. **像素级的排版与错误洞察**：
   - *“时间比较长...只拆分成了3个模块...对行高进行了统一修改，我希望保持原有格式...”*
   - *“你简直是扯淡...AA30, AB30...这些都是翻译不全的，你却说翻译没问题。”*
   - 直接甩出具体的坐标（AA30, AA42），用无可辩驳的证据倒逼 AI 去溯源底层代码的逻辑断层，而非停留在表面的“代码已修改”。
3. **直击本质的“拷问”**：
   - *“目前切块的逻辑和依据是什么？怎么把这些冗长的内容分隔开来的。请用语言描述。”*
   - 要求 AI 脱离代码细节，用自然语言把架构逻辑讲清楚。这有效地打破了 AI 的“黑盒思维”，使其不得不重新审视自己设计的荒谬之处（如标点切割法）。

## 3. 铭哥的架构哲学与思想特点

通过上述的碰撞，铭哥为本项目注入了极具前瞻性的架构思想。这些思想将成为 V2.0 乃至更长远产品化的核心准则：

### 3.1 第一性原理：让大模型做大模型该做的事
- **思想**：*“作为大语言模型，优点是语言方面，做翻译非常适合。但是你让他做判断，绝对不合适。”*
- **落地**：废除了代码中冗杂的 5 层分类漏斗和 `isalpha()` 判断。将系统提示词（System Prompt）打造为“行业知识库”，让大模型自己去理解什么是工业语境、什么是该保留的料号。**代码只负责数据流转，大模型负责语义理解。**

### 3.2 极简的结构美学：摒弃过度设计
- **思想**：*“切分的目的是因为内容太多，大模型处理困难，因此直接根据内容长短大小区分。看平均单元格字数，或者直接按照10行一组切分即可，最简单也最不容易出错。”*
- **落地**：推翻了花里胡哨的“标点符号切分法”，采用了基于“平均字数打包发送 (Dynamic Batching)”的简单逻辑。这不仅解决了语境割裂的幻觉问题，更将 API 调用次数降低了一个数量级，直接化解了限流难题。

### 3.3 数据与格式的绝对隔离：零损耗原则
- **思想**：任何自动化工具都不能以破坏用户的原始心血（格式排版）为代价。
- **落地**：舍弃了简单粗暴的 `openpyxl` 写入覆盖，转而使用原生 `AppleScript` 像操作鼠标一样进行精准文本替换，把排版的控制权永远留给了人类。

### 总结
铭哥的指导思想可以概括为：**“信任模型智力，剥离冗余逻辑；坚守格式底线，用最朴素的机制解决最复杂的并发。”** 这种大巧不工的工程思维，是本工具能够脱胎换骨的核心驱动力。
