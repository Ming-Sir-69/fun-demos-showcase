# Excel Intelligent Translation - 架构演进与技术复盘白皮书
> 本文档无损提取自全局 `error` 目录，提炼了该项目从零到一、从漏洞百出到极致鲁棒的完整架构演进与防呆设计（Poka-Yoke）思路。

## 1. 核心架构演进：从正则粗暴替换到“无损排版还原”
**背景与痛点**：
为了解决大模型（如 Kimi, DeepSeek 等）在翻译时试图复现原文的排版（如几十个连续空格）导致 Token 浪费和生成死循环的问题，早期版本在数据预处理时使用了 `re.sub(r' {2,}', ' ', text_val)`。虽然成功防呆了 LLM，但也导致像 `检验规范 (SIP)                      页码: 1/1` 这样的排版在翻译后彻底丢失，格式严重错乱。

**终极重构方案 (Layout Preservation)**：
1. **正则分割 (Split)**：废弃全局替换。使用 `parts = re.split(r'( {2,}|\t+)', original_val)` 将单元格切分为交替的 **“文本块”** 和 **“排版空白块”**。
2. **纯净分发 (Distribution)**：只对纯净的“文本块”进行分类拦截、去重并送给大模型。大模型依然看不到多余的空格，完美防呆。
3. **原位组装 (Reassembly)**：拿到译文后，循环原始 `parts` 数组，将原样保留的“排版空白块”与“译文块”按原序拼接（`译文A + 长空格 + 译文B`）。
**结论**：彻底实现了“**翻译前剥离格式空格，翻译后包含格式空格拼接**”，使 Excel 获得了 100% 的无损格式还原。

## 2. 字典管理：归一化引擎与闭环纯净化防呆
**背景与痛点**：
早期的本地字典死板地要求中英文括号、空格必须完全一致。导致字典中出现了 `检验规范 (SIP)`、`检验规范(SIP)` 等大量冗余变体。不仅降低了命中率，大模型返回的带空格变体还会不断污染字典。

**终极重构方案 (Dictionary Normalization)**：
1. **归一化算法**：引入 `normalize_text`，在加载和匹配字典时，将文本的全角符号转半角、剔除所有空白符、转小写。无论原文怎么排版，底层都映射为唯一的 `检验规范(sip)`。
2. **追加防呆 (Poka-Yoke in Append)**：
   在将大模型的译文写入本地字典 `local_dict_mapping.txt` 前，强制执行：
   - 剔除首尾排版残留 (`strip()`)。
   - 利用 `normalize_text` 检查字典中是否已存在该词条的变体。如果存在，坚决不写入。
   - 过滤超长句子和带换行符的复杂段落，确保字典里只积累“专业词汇/短语”。
3. **全量数据清洗 (Data Cleansing)**：编写了独立的 `cleanup_dict.py`，对历史存量字典进行了全量归一化扫描，剔除了所有同义不同排版的废数据。

## 3. 动态数据拦截：基于第一性原理的分类器升级
**背景与痛点**：
字典库的核心目的是积累高频、专业、复用率高的词条以降低 Token 消耗。但诸如“页码：1/4”、“日期：2024/08/13”、“作成：张三”等内容，每个项目都在变，如果送去翻译并加入字典，会造成严重的 Token 浪费和字典污染。

**终极重构方案 (Dynamic Data Excluded)**：
在 `text_classifier.py` 中新增前置漏斗 `is_ignore_pattern`。
- 使用正则精确拦截带有 `页码/Page`、`日期/Date`、`版本/Version` 前缀的字符串，以及带有 `审核/制定/担当` 前缀的人名组合。
- 一旦命中，分类器直接返回 `KEEP_ORIGINAL`。它们将直接被原样写回 Excel，完全绕过了大模型翻译，也绝不会进入字典库，保持了字典的绝对专业性和高复用度。

## 4. 浮动文字框图 (Shapes) 的独立渲染层扫描
**背景与痛点**：
在 SIP 检验规范中，“客诉记录 -> 性能检验”等流程图模块是插入的“形状 (Shapes)/文本框”。`xlwings` 的 `used_range.value` 只能探测底层单元格 (Cell) 的物理数据，导致这些浮动文字完全漏翻。

**终极重构方案**：
1. 在 `main_pipeline_full.py` 引入针对 Shapes 层的独立扫描阶段：`for shape in sheet.shapes:`。
2. 将 `shape.text` 提取并压入同一个翻译流水线。
3. 在底层写回时，加入类型断言防呆：`if isinstance(cell, xw.Shape): cell.text = final_val else: cell.value = final_val`，确保文本框和普通单元格的数据覆写互不干扰。

## 5. 跨平台 IPC 性能雪崩与哈希查重优化
**背景与痛点**：
重构为 `xlwings` 后，由于频繁跨进程调用 `cell.merge_cells` 导致通信雪崩，且列表去重 `any(...)` 耗时 $O(N^2)$，程序在路由阶段极度卡顿。
**终极重构方案**：
1. **批量拉取**：使用 `all_values = used_range.value` 一次性读取全部数据到 Python 内存。直接依靠 `val is not None` 过滤合并单元格非左上角坐标，彻底删除 `merge_cells` 判断。
2. **哈希去重**：引入 `seen_texts = set()`，将 $O(N^2)$ 的列表遍历优化为 $O(1)$ 的集合查重。上万个单元格的路由耗时从几分钟骤降至 30 秒内。

## 6. 模型选择与高并发长连接死锁 (Timeout)
**背景与痛点**：
在使用开源/免费 API 节点（如 Nvidia nemotron-3-super-120b）进行批量并发翻译时，极易触发 API 网关的高频限流甚至连接死锁，导致主线程无限期挂起。
**终极重构方案**：
1. **API 超时熔断**：所有 API 请求强制加入 `timeout=15.0`。
2. **指数退避机制 (Exponential Backoff)**：捕获 HTTP 429 (Rate Limit) 错误，进入动态递增的 `time.sleep()`，等待额度恢复后自动重试。
3. 确立了将 `moonshot-v1-128k` 或类似稳定商用 API 作为生产环境基线的准则。

## 7. 知行合一的原子化字典与语义保护机制 (Atomic Dictionary & Semantic Protection)
**背景与痛点**：
为了实现字典的高效复用，希望将“核准：张三”拆分为“核准”和“张三”独立入库。早期方案是在送给大模型之前，就用冒号切分文本。这导致长句的语义被破坏，大模型收到一堆碎片后 JSON 数组解析崩溃，连累同批次的长句（如 E11）翻译失败。
此外，读写逻辑不对称：写入字典时拦截了动态参数（如 `12V`, `L≤2.3mm`），但读取时如果字典里存在历史脏数据，依然会被命中。

**终极重构方案 (Read-Write Symmetry)**：
1. **语义保护 (Semantic Integrity)**：送给大模型翻译前，**绝对不进行拆分**，将原汁原味的整句送给 LLM，保证上下文完整，完美输出 JSON 数组。
2. **原子化拆分入库 (Atomic Dictionary)**：仅在**匹配本地字典**和**向本地字典追加新词**时，利用冒号 `:` 作为物理切割刀。将 `制作：文伟栋 = Created by: Wen Weidong` 拆分为 `制作=Created by` 和 `文伟栋=Wen Weidong` 独立入库，实现完美交叉复用，且不涉及复杂的 NLP 语义切割，避免机翻语病。
3. **动态参数防呆下沉**：将 `is_dynamic_parameter` 规则统一收口在 `text_classifier.py`。在查字典前和写字典前双向拦截，确保字典库永远不被数字和比较符污染，实现了系统架构上真正的“知行合一”。

## 8. 工程化重构与打包预备 (Engineering & Packaging Readiness)
**背景与痛点**：
项目在经过多次迭代后，根目录堆积了大量的废弃脚本、测试文件和资源，呈现出典型的“脚本乱炖”状态。这种结构不仅难以维护，在使用 PyInstaller 等工具打包为可执行文件时，会导致无关资源全部被封装，极大增加体积并引发潜在的依赖冲突。此外，在重构目录结构时，极易引发 `No module named` 等模块引用链断裂错误。

**终极重构方案 (Project Reorganization)**：
1. **职责分离 (Separation of Concerns)**：
   - 建立 `src/` 作为核心代码沙箱（包含 `core/` 与 `scripts/`），与业务数据严格隔离。
   - 建立 `data/` 作为资源池（下设 `original_excel_doc/` 与 `dictionary/`），确保输入输出和字典落盘的绝对安全。
   - 建立 `archive/` 与 `project_context/` 封存历史资产与架构文档。
2. **依赖防呆与环境隔离**：
   - 坚持使用 `.venv` 虚拟环境。在打包时可精准抽取依赖（如仅包含 `xlwings` 和 `openai`），拒绝全局环境带来的几百兆垃圾包污染。
   - 编写 `run.sh` 入口脚本，实现一键自动激活虚拟环境并运行主程序，抹平使用门槛，兼顾了开发时的干净环境与交付时的丝滑体验。
3. **模块化寻址 (Absolute Pathing)**：全面废弃相对路径，改用基于 `os.path.dirname(os.path.abspath(__file__))` 的动态寻址机制，并使用 `from core.xxx import yyy`，确保代码在任何层级被调用都能精准定位资源。
