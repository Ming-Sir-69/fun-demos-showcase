## 核心目标

本轮不再用多张官方样本分散验证，而是改为围绕一个统一目标图做等预算串行验证：

`文字描述 / 结构 spec / 风格说明 -> AI 抽语义结构 -> AI 输出结构 JSON -> 脚本渲染 drawio XML -> AI 验收 -> 铭哥人工验收 -> 输出交付文件`

**关键转折**（2026-06-20）：chart1 验证 5 轮修复后明确——AI 适合做"内容决策"（多少层、放什么节点、连线语义），不适合做"格式输出"（坐标计算、方式点规划、style 拼接）。拆为两层：**AI 层只输出 JSON 结构 → 脚本层执行全部规则并渲染**。参见 `00_Key_Decisions.md`。

## 本轮验证问题

1. 哪条单工具路线最适合复刻 `T1` 这种咨询报告风、低饱和、分层系统架构图。
2. AI 是否可以主要负责结构与语义，而把连线、吸附、尺寸联动尽量交给工具系统。
3. 同一份风格说明能否稳定约束不同路线的输出审美，而不是每轮重新摸索。
4. 已知错误模式是否可以作为前置门禁复用，而不是再次消耗正式预算。

## 下一阶段（2026-06-20 规划）

**演进路径**：先指南层验证规则 → 再模板层固化规则 → 验收层保底。不跳级。

### Layer 1：指南层（当前阶段 — 验证规则正确性）

目标：将已发现的"出错模式"改为"防产生规则"，通过 `guides/` 的决策树写法验证规则是否正确。

操作：
- 把避坑手册中的每个错误模式改写为 **if-else 决策树**（非选项列表）
- 在 01_绘制流程 Step 2/3 中增加"生成时即强制"的约束（如"target 是 label → endArrow=none"）
- 多场景验证（chart2/chart3/chart4 逐一跑通）
- **验证标准**：新 Session 读 guides/ 后能零轮修复通过 C1-C7，且路径/箭头/间距无问题

### Layer 2：模板层（待指南层验证通过后启动）

目标：将已验证的规则写成 `build_diagram.py` 函数族，让 AI 从"描述+计算"降级为"填参数+调函数"。

操作：
- 封装坐标计算、出口方向选择、间距公式、颜色映射、总线检测为可调用函数
- AI 只需写 YAML 结构描述文件和调用 `build_diagram("chart.yaml")`，不碰坐标/style/waypoint
- 跨图复用（chart1 / chart2 共享颜色映射和间距公式）

### Layer 3：验收层（长期兜底）

目标：C1-C7 作为"脚本有 bug 时"的最后防线，不再作为发现问题的主力手段。

操作：
- 验收项同步升级（如 C7 加出口方向检测、C1 自动推荐间距偏移量）
- 验收失败时自动打印"预期 vs 实际"对比和修复建议

### 三层的优先级关系

```
Layer 1（指南层）描述规则 → Layer 2（模板层）固化规则 → Layer 3（验收层）兜底规则
         ↑                               ↑                              ↑
   防"意识不到"                     防"做错了"                     防"漏出去"
```

**不要跳级**：Layer 1 验证过的规则才进入 Layer 2。未经验证的规则不写代码，避免代码改了又改。

## 通过标准

- 至少 1 条路线能在预算内产出接近 `T1` 目标风格与结构的可交付结果。
- 所有正式通过版本都具备 `.drawio/.svg/.pdf` 或等价的可验收交付链路。
- 人工微调成本原则上控制在总时间的 30% 以内。
- 结构、风格、连线和导出问题都可以被 AI 验收明确指出，而不是依赖口头印象。
