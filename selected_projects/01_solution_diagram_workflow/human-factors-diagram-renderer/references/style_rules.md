## 间距公式（减法公式）

### 公式

```
G = 50 + N × 25 − (N − M) × 12
```

### 符号

| 符号 | 含义 | 如何计数 |
|------|------|---------|
| **N** | 穿过该间隙的逻辑线总数 | 数所有从间隙上方到下方的连线（合并 A→标签→B 为 1 条） |
| **M** | 有标签的线数量 | 只数间隙内有可见标签框的线 |

### 临界规则

- N ≠ M。**只看标签框数就是漏算**。
- 每层间隙各自独立计算。
- 间隙上下呼吸边距：pad_top = pad_bottom = 24px
- 多标签时错开：标签间隔 = 标签高 + 8px

### 常见场景的 G 值

| N | M | G | 场景 |
|:-:|:-:|:--:|------|
| 1 | 0 | 75 | 单条线无标签（人审→知识库） |
| 2 | 0 | 100 | 2条裸线 |
| 2 | 2 | 100 | 2条有标签线 |
| 4 | 2 | 126 | 4条线其中2条带标签 |
| 5 | 2 | 139 | T1场景参考 |
| 6 | 3 | 164 | 6条线3条带标签 |
| 8 | 0 | 250 | 8条裸线（8条分发/返回线） |

## 连线语义

| 语义 | style | 描述 |
|------|-------|------|
| 主数据/控制流 | `endArrow=block;endFill=1;strokeWidth=1.5;strokeColor=#3F4447;` | 实线+实心箭头 |
| 协同/辩论流 | `dashed=1;dashPattern=8 6;endArrow=block;endFill=1;strokeWidth=1.5;strokeColor=#3F4447;` | 虚线+实心箭头 |
| 经验沉淀/审计流 | `dashed=1;dashPattern=2 2;endArrow=open;endFill=0;strokeWidth=1;strokeColor=#64748B;` | 点线+空心箭头 |

### visual_family

| visual_family | 定义 | 复用场景 |
|------|------|------|
| `solid_main` | 实线 + 实心箭头 | 主控制流、系统接口、平台支撑 |
| `dashed_agent` | 长虚线 + 实心箭头 | Agent 协作、辩论、调度 |
| `dotted_knowledge` | 点线 + 空心箭头 | 知识沉淀、审计、回流 |

### 业务语义 → 视觉线型映射

| edge.type | visual_family |
|------|------|
| `control_flow` | `solid_main` |
| `system_interface` | `solid_main` |
| `platform_support` | `solid_main` |
| `agent_flow` | `dashed_agent` |
| `knowledge_flow` | `dotted_knowledge` |

### 路由规则

- 必须使用正交路由（`edgeStyle=orthogonalEdgeStyle`）
- 连线最后一个方式点必须在目标节点的端口范围内（顶部或底部垂直入口，不可从侧面水平穿入）
- 同语义线全图保持一致，不得一处实线一处虚线
- `flowchart_decision_tree` 的多分支连线必须 fan-out，不得把所有分支压到同一出口点

## 图例格式

每个图例项 = 40-60px 线段 + 8px 间隙 + 文字标签

- 图例内容整体居中
- 图例文字与边框之间保留呼吸空间
- 图例展示的线型必须直接复用真实 edge style，不允许画“近似版”
- 当同一张图同时出现连线图例和节点颜色图例时，必须分组标注：`连线含义`、`节点颜色`
- 节点颜色图例使用“小型圆角节点缩略框”，不要用普通小色块，避免和泳道背景色混淆
- 泳道/分层/大容器背景如果已有清晰标题，一般不单独写颜色图例；背景色只做分区，节点颜色才做语义分类
- 图例与主图主体之间至少保留 44px 呼吸距离；底部图例区由 renderer 统一预留，不手工贴边

## flowchart_decision_tree 节点风格

| node.type | 推荐形状/色系 | 用途 |
|------|------|------|
| `flow_start` | 圆角起点，浅蓝底 | 入口事件 |
| `flow_process` | 常规圆角卡片，浅蓝底 | 中间事实或动作 |
| `flow_decision` | 菱形，浅米底 | 主判断点 |
| `flow_condition` | 胶囊或轻量节点，白底灰边 | 条件文字承载体 |
| `flow_result` | 结果卡片，浅绿底 | 分支结论 |
| `flow_output` | 深色底闭环卡片 | 最终输出/收束点 |

### 判断树布局规则

- 判断节点使用菱形
- 条件节点使用胶囊或轻量节点，不用原生 edge label
- 多个判断分支必须 fan-out，不能全部共用同一个端口
- 最终输出节点可以使用深色底，突出闭环终点

## draw.io 页签命名

每个独立 `.drawio` 文件也必须写入工作簿页签名。

官方 XML 结构中，底部页签来自：

```xml
<mxfile pages="1">
  <diagram id="page_xxx" name="图表名称">
```

规则：

- `pages` 必须等于实际 `<diagram>` 数量；当前单图交付固定为 `1`
- `<diagram name="...">` 必须使用 JSON 中的 `page_name`
- 不允许省略 `name`，否则 diagrams.net 会显示默认的 `Page-1` / `第 1 页`
- 不允许使用临时 id（如 `dsl_demo`），页 id 应由页签名稳定生成，便于回归对比

---

## 标签规则

- 补充说明类标签应紧凑，不应占据过宽空间
- 标签宽度可按文字长度估算，并设置最大宽度
- 同一间隙中的多个标签优先纵向错开，不横向硬拉宽

线段 style 必须与图中使用的风格完全一致（相同 strokeWidth、dashPattern、arrow 类型、颜色）。

---

## 画布

- 默认 16:9（1600×900）
- 内容决定实际尺寸，不强制固定比例
- 多层+多间距时增加 pageHeight
