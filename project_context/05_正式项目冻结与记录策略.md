# 正式项目冻结与记录策略

## 1. 正式项目冻结

当前正式小项目冻结为：

1. `solution-diagram-workflow-mvp`
2. `Excel intelligent translation`

不再作为正式小项目的项目：

1. `AI产品经理作品集`

说明：

1. 作品集不删除。
2. 作品集仍可作为大项目的结构设计参考来源。
3. 但它不再承担主展示项目的角色。

## 2. 选择这两个项目的核心原因

### `solution-diagram-workflow-mvp`

它负责证明：

1. 你会在正式开发前做小成本验证。
2. 你能把 POC 与 NPI 的思路结合起来。
3. 你会主动识别短板、调整验证路径、拆分内容与结构。
4. 你不是等研发完整做完后再评价，而是走在研发前面先逼出关键风险。

### `Excel intelligent translation`

它负责证明：

1. 你不只会探索，也会把东西做成可稳定使用的工具。
2. 你会权衡性能、成本、格式保护、并发和用户体验。
3. 你有本地与线上双路、知识复利和持续优化的思维。
4. 你能把验证过的价值沉淀成可长期使用的系统。

证据边界：

1. 它的原始 Session 记录不完整
2. 因此它主要证明“落地能力、取舍能力、产品化能力”
3. 不主要承担“完整原始探索链条”的展示职责

## 3. 两个项目组合后的互补关系

这个组合的目的不是重复证明“我会做工具”，而是形成闭环：

1. `solution-diagram-workflow-mvp` 证明前端探索、路径设计和验证思维。
2. `Excel intelligent translation` 证明后端落地、稳定性和复利能力。
3. 两者合起来，才更像一个 AI 产品经理在 ToB / ToG 场景中的完整工作方式。

## 4. 记录策略

不单独产出“历程总结文档”。

原因：

1. 这次对话的完整上下文已经通过 `project_context/transcripts/` 无损记录。
2. 对 AI 来说，原始长文本比再次压缩的“历程摘要”更有价值。
3. 对人类读者来说，重复写历程会增加阅读负担。
4. 因此只保留高密度的规则、决策和待定项，把长过程留在 transcripts。

## 5. 人类与 AI 的分工式阅读

### 人类读者

优先读取：

1. 为什么选这两个项目
2. 每个项目如何快速看懂
3. 每个项目的核心证据在哪里

### AI

优先读取：

1. 大项目中的规则与结构化文档
2. 各小项目的高密度架构与决策文档
3. `project_context/transcripts/` 中的长文本上下文

补充：

1. `solution-diagram-workflow-mvp` 可以更多承担“原始探索链条”的读取价值
2. `Excel intelligent translation` 则更多承担“复盘后的高密度落地证据”的读取价值
