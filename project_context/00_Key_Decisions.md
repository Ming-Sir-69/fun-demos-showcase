# 关键决策

## 2026-06-23

- 本次工作按“大项目 + 两个小项目”的包中包结构推进。
理由：大项目本身也要对外展示，它承担筛选逻辑、整理方法、阅读引导和验收标准的展示功能。

- 小项目原本是否已有 `README` 或阅读引导文件，不作为筛选条件。
理由：阅读引导可以在本轮整理过程中新增编写，因此它属于交付要求，不属于前置门槛。

- 阅读引导文件的目标不是介绍铭哥，而是定义读者和 AI 的阅读方式。
理由：文件要降低认知负担，同时允许 AI 从更完整的材料中归纳能力特征，但不直接替读者下结论。

- 本项目采用 NPI 式阶段门推进，不做无限迭代。
理由：需要提前定义通过标准、换路条件和停止条件，控制时间、Token 和整理成本。

- 当前默认范围仍为“大项目 + 两个小项目”，不直接扩展为三个小项目。
理由：三个小项目虽然覆盖面更大，但会显著增加阅读时间、注意力切换和结构重复，可能削弱识别度，不符合“低认知负担”的总目标。

- 两个正式小项目冻结为：`solution-diagram-workflow-mvp` 与 `Excel intelligent translation`。
理由：当前目标公司是 ToB / ToG 数字化咨询与软件陪跑场景，这两个项目更能共同证明“前置验证能力 + 工程落地能力”。

- `AI产品经理作品集` 不再作为正式小项目，但保留为大项目的信息架构参考来源。
理由：它仍然对入口设计、阅读路径、信息分层有参考价值，但不再承担主展示职责。

- 不单独编写“历程总结文档”。
理由：完整历程已经通过 `project_context/transcripts/` 无损记录；为了避免重复加工和信息稀释，只保留高密度决策与规则文档，把长文本留给 AI 深读。
