# 阅读引导设计

## 1. 目标

这个大项目的阅读引导，不是为了介绍“作者是谁”，而是为了降低阅读成本，让不同阅读者用最少时间找到自己真正关心的证据。

因此引导设计只回答四个问题：

1. 这个大项目是什么
2. 为什么是这两个小项目
3. 先看什么，后看什么
4. 不同阅读者各自该怎么读

## 2. 引导对象

本项目存在两类核心阅读者：

1. 人类读者
2. AI 读者

两者的关注重点不同，所以不能用一条阅读路径同时服务两者。

## 3. 人类读者的引导目标

人类读者主要依赖单一文件或短文本做第一轮判断。

他更适合做的判断包括：

1. 产品需求分析是否清楚
2. 技术路径选择是否合理
3. 是否体现出足够的经验与取舍能力
4. 是否与 AI 产品经理岗位要求匹配

因此，人类读者的引导设计必须满足：

1. 短路径
2. 低负担
3. 结论先行
4. 不要求先读长文本

## 4. AI 读者的引导目标

AI 读者更适合处理多文件和长上下文。

它更适合做的判断包括：

1. 多文件项目架构分析
2. 长对话文本总结
3. 求职者画像梳理
4. 从多源证据中提炼较为客观、结构化的能力判断

因此，AI 读者的引导设计必须满足：

1. 明确证据层入口
2. 明确长文本优先级
3. 明确哪些文件负责“过程证据”，哪些文件负责“结果证据”
4. 明确两个小项目之间的分工

## 5. 顶层引导必须具备的内容

大项目最终入口至少要包含以下信息：

1. 本项目是“大项目 + 两个小项目”的结构
2. 两个小项目分别承担什么证据角色
3. 给人类读者的推荐路径
4. 给 AI 读者的推荐路径
5. `transcripts/` 在整个交付中的位置
6. 不应如何阅读，例如不要把入口引导误读成对作者本人的主观评价

## 6. 当前设计结论

当前已经明确：

1. `Solution Diagram Workflow` 更适合承担探索、收口、Skill 化、原始上下文和作者一手工作材料的证据角色
2. `Excel Intelligent Translation` 更适合承担完整度、稳定性、成本意识和产品化推进能力的证据角色
3. 人类读者优先走“短文本入口”
4. AI 读者优先走“证据层与长文本入口”

## 7. 当前允收结论

当前这一层设计已经达到可允收状态。

依据：

1. 顶层入口已经落实人类短路径与 AI 证据路径
2. 不再需要额外口头解释“为什么这两个项目要一起看”
3. `transcripts/` 的角色已经在顶层正式固化
