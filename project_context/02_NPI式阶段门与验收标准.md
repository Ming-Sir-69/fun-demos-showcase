# NPI式阶段门与验收标准

## 1. 设计原则

本项目按“低资源、低改动、明确门禁”的方式推进。

原则如下：

1. 先冻结标准，再做整理。
2. 每阶段只追求“足够通过”，不追求无限打磨。
3. 每阶段都要有进入下一阶段的明确门槛。
4. 若连续迭代效果仍不足，则换路径，不继续加资源硬磨。

## 2. 阶段划分

### Phase 0：项目定义冻结

目标：

1. 定义大项目角色。
2. 定义筛选标准与排除红线。
3. 定义后续所有验收标准和换路条件。

通过标准：

1. 大项目与两个小项目的关系已写清。
2. 筛选条件与验收条件已分开。
3. 已定义不做无限迭代。

### Phase 1：候选池收缩

目标：

1. 从现有项目中筛出 5 个候选。
2. 从 5 个候选中识别 3 个强候选。
3. 再从 3 个强候选中收缩到 2 个正式整理对象。
4. 确定“短文本记录”和“长文本记录”的分工方式。

通过标准：

1. 每个候选都有入选原因与风险说明。
2. 三个强候选的功能分工与重叠关系已判断清楚。
3. 两个正式项目的排除风险可控。
4. 两个正式项目的整理成本在可接受范围内。
5. 已确认不单独产出冗余历程文档。

### Phase 2：信息架构设计

目标：

1. 设计大项目目录结构。
2. 设计两个小项目的对外目录结构。
3. 明确“人类快读路径”和“AI深读路径”。

通过标准：

1. 每个项目都有单一入口文件。
2. 每个入口文件都能引导 3 分钟内完成首轮浏览。
3. 长文本材料与速读材料分层清楚。

### Phase 3：内容整理与脱敏

目标：

1. 复制并整理两个小项目。
2. 删除或替换不适合外发的材料。
3. 补充缺失的阅读引导和索引文件。

通过标准：

1. 无明确涉密材料残留。
2. 核心开发证据链仍然完整。
3. 不依赖口头解释，也能看懂主要主线。

### Phase 4：阅读测试与换路判断

目标：

1. 用人类阅读负担视角检查。
2. 用 AI 长文本分析视角检查。
3. 判断是否需要小修，还是应整体换路径。

通过标准：

1. 人类可在短时间定位项目目标、结构、Demo、关键证据，并完成产品需求分析、技术路径选择、经验判断和岗位适配度的第一轮主观判断。
2. AI 可从多文件与长文本中提取开发过程、方法论、项目架构关系和能力证据，并对求职者画像做较为客观的结构化总结。
3. `Solution Diagram Workflow` 中的 `transcripts/` 已被明确用作作者一手工作材料的核心入口。
4. `Excel Intelligent Translation` 已被明确定位为完整度、稳定性和产品化能力的证据项目。
5. 引导文件未越界到“评价人”的层面。

## 3. 换路条件

满足以下任一情况时，不继续局部打补丁，直接换路径：

1. 同一项目连续 2 轮整理后，主线仍不清楚。
2. 为了可读性需要删除的内容，已经伤及核心证据链。
3. 为了脱敏需要替换的内容过多，导致项目真实性下降。
4. 引导文件需要大量解释项目背景才能读懂，说明入口设计失败。
5. 三项目方案相比两项目方案，没有明显新增价值，却显著增加阅读负担。

## 4. 停止条件

满足以下条件，即视为当前阶段可验收，不再继续细抠：

1. 已有明确入口。
2. 已有清晰阅读顺序。
3. 已能支撑人类短路径与 AI 证据路径两种模式。
4. 已无明显涉密风险。
5. 修改成本开始高于预期收益。
6. 项目数量与阅读体量处于可控范围。
