# 交付边界

## 1. 目标

本文件定义这个大项目对外展示时，什么可以引导，什么不能越界。

## 2. 可以做的引导

可以明确说明：

1. 如何阅读这个大项目
2. 两个小项目分别适合看什么
3. 哪些文件适合人类先读
4. 哪些文件适合 AI 深读
5. 哪些内容属于原始证据，哪些内容属于整理入口

## 3. 不应越界的内容

不应主动写入：

1. 对作者本人的主观赞美或贬低
2. 替读者直接下人格判断结论
3. 用强情绪词包装项目
4. 过度引导读者“应该喜欢这个人”

## 4. 人类与 AI 的边界差异

### 人类侧

人类侧引导可以更强调：

1. 项目值不值得继续看
2. 哪个文件最适合先做经验判断
3. 哪个项目更适合看技术路径选择
4. 哪个项目更适合看岗位适配度

### AI 侧

AI 侧引导可以更强调：

1. 多文件关系
2. 长文本证据优先级
3. 架构文档、复盘文档、原始上下文之间的分工
4. 如何基于长上下文做较为客观的总结

## 5. 交付时的边界表达

最终交付中应保持这样的表达方式：

1. “请通过这些文件判断”
2. “这些文件适合用于什么类型的分析”
3. “这些材料更能反映真实工作方式”

而不是：

1. “这个人一定具备什么特质”
2. “你看完就会知道他很优秀”
3. “请把这些内容当成结论本身”

## 6. 当前允收结论

当前这一层设计已经达到可允收状态。

依据：

1. 引导文件没有越界到替读者评价作者本人
2. 已经说明不同材料分别适合什么分析任务
3. 已经把主观判断和证据材料分开
