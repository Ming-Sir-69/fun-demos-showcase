# Solution Diagram Workflow 整理草案

> 状态：待铭哥确认
> 说明：以下内容是对外版本的第一版整理提案，不代表已经最终定稿。

## 1. 对外版本建议保留什么

建议优先保留：

1. 项目总入口与项目定位
2. `project_context/` 中能证明路线选择、验收逻辑和收口标准的高密度文档
3. `guides/` 中能体现操作流程、风格规则、避坑与验收的方法文件
4. `specs/`、`templates/`、`src/`、`tests/` 中能证明 DSL、渲染器和测试闭环的核心材料
5. `human-factors-diagram-renderer/` 作为最终 skill 包形态
6. 代表性输出与回归样例，如架构图、判断树、RAG 流程图

## 2. 对外版本建议删什么

建议优先删除或隔离：

1. 明确含有 `8D` 语义和样例的资产
2. 与 8D 强绑定的实验文件、图、说明和产物
3. 非必要的历史路线残留，如果它们不能提升读者判断效率
4. 与项目主线无关的系统文件和归档噪音

当前高风险区：

1. `assets/8d-other-diagrams/`
2. 含 `8d` 命名的样例与实验文件
3. 直接引用 8D 目标图的说明文本

## 3. 快读路径怎么设计

建议快读路径控制在 3 层：

### 第 1 层：这是什么

回答：

1. 它不是普通画图工具
2. 它是把“AI 做内容决策”与“脚本做确定性渲染”拆开的验证型项目

### 第 2 层：为什么值得看

回答：

1. 它体现了 POC 与 NPI 结合的思路
2. 它体现了前置验证、短板识别、换路与收口标准

### 第 3 层：证据在哪里

快速跳转到：

1. 关键决策
2. Demo 收口标准
3. 一两个代表样例
4. skill 包与测试闭环

## 4. AI 深读路径怎么设计

建议 AI 深读顺序：

1. `project_context/00_Key_Decisions.md`
2. `project_context/01_mvp_goal.md`
3. `project_context/DEMO_EXIT_CRITERIA.md`
4. `project_context/05_error_index.md`
5. `project_context/35_skill_maturity_assessment.md`
6. `guides/`
7. `specs/diagram_dsl_v0_1_spec.md`
8. `src/`
9. `tests/`
10. `transcripts/` 或大项目中的长文本上下文

## 5. Phase 2 验收标准建议

对外信息架构设计阶段，通过标准建议为：

1. 首屏入口能在 1 分钟内说明项目角色与边界
2. 人类读者能在 3 分钟内找到“为什么它不是普通画图工具”
3. 人类读者能在 5 分钟内看到验证思路、代表样例和收口标准
4. AI 能从深读路径中恢复出路线选择、能力边界和未完成项
5. 删除 8D 相关内容后，主线仍然成立

## 6. 当前最需要铭哥决策的点

1. 8D 相关材料是彻底删除，还是移入内部归档不对外展示
2. 历史路线文件保留到什么程度，才既能证明探索深度，又不造成阅读噪音
3. 对外主入口更偏“方法论型”，还是更偏“skill 产品型”
