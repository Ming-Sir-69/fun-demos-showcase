# 项目组合建议

## 1. 当前候选结论

当前三个强候选是：

1. `solution-diagram-workflow-mvp`
2. `Excel intelligent translation`
3. `AI产品经理作品集`

这三个项目都具备对外展示价值，但不建议默认全部纳入正式交付。

## 2. 当前冻结结论

当前正式组合已经冻结为：

**大项目 + 两个小项目**

两个小项目分别是：

1. `solution-diagram-workflow-mvp`
2. `Excel intelligent translation`

## 3. 不建议默认做三个小项目的原因

### 原因 1：阅读体量会明显膨胀

大项目本身已经承担：

1. 总入口
2. 筛选逻辑
3. 阅读引导
4. 验收标准
5. 组合解释

如果再放三个小项目，读者进入材料后会同时面对：

1. 一个方法项目
2. 三个独立项目
3. 四套不同的上下文与入口

这会增加阅读耗时和注意力切换成本。

### 原因 2：作品集与大项目存在功能重叠

`AI产品经理作品集` 的强项在于：

1. 信息架构
2. 人机交互
3. 展示逻辑
4. 对外阅读路径设计

而大项目本身也承担一部分相同职责。

所以如果再叠加三个小项目，容易出现“包装层过厚”的问题：

1. 大项目在讲怎么读
2. 作品集也在讲怎么读
3. 读者可能觉得结构很完整，但主线不够集中

### 原因 3：三个都强，不等于三个一起最优

单项强，说明项目本身成立。

组合最优，要求：

1. 分工互补
2. 不重复证明同一种能力
3. 不让最重要的特征被淹没

三个项目同时进入正式交付时，反而可能让你的特征分散。

## 4. 当前冻结组合的原因

### 原因 1：更匹配目标公司的业务场景

目标公司是 ToB / ToG 数字化咨询与软件陪跑场景。

因此更关键的能力信号是：

1. 前置验证与路径判断
2. 场景化抽象与方法创新
3. 稳定落地与长期复利

`solution-diagram-workflow-mvp` 与 `Excel intelligent translation` 的组合更贴近这些信号。

### 原因 2：两者能形成“探索 + 落地”的闭环

1. `solution-diagram-workflow-mvp` 更偏前置探索、POC、NPI、方法重构。
2. `Excel intelligent translation` 更偏稳定工具、工程闭环、成本控制和持续使用。

两者共同构成“先验证，再落地”的完整能力链。

### 原因 3：作品集更适合作为辅助资产

`AI产品经理作品集` 的价值依然存在，但它更适合：

1. 提供信息架构参考
2. 提供入口组织方式参考
3. 辅助优化大项目的阅读体验

它不再承担主项目展示职责。
