# 第二轮副本收缩记录

## 1. 本轮目标

本轮不是继续补材料，而是主动收缩两个副本的阅读面。

核心原则只有两个：

1. 让人和 AI 都能更快抓到真正要展示的东西
2. 不让旧方案输出、重复结构和无效入口稀释判断

## 2. Solution Diagram Workflow 的收缩原则

本轮确认，这个副本的展示中心不再是“整个流程图项目”，而是：

`human-factors-diagram-renderer/`

也就是最终已经收口成型、可以独立复用的 Skill。

因此本轮做了三件事：

1. 把入口文件改成以最终 Skill 为中心，而不是以整个工程树为中心
2. 删除旧版输出产物和重复实现，避免错误路线输出继续占据阅读带宽
3. 只保留支撑 Skill 成立的关键决策、验收规则、错误索引和原始上下文

这里特别强调：

- “内容与渲染拆开”在这个项目里保留为关键决策拐点
- 但它不是首页要高举的主口号
- 因为这不是项目一开始就确定好的方案，而是过程中收敛出来的结果
- `transcripts/` 不只承担“过程记录”功能，也承担“作者一手工作材料”功能，适合 AI 深入阅读长文本后判断真实工作方式与个人特征

## 3. Excel Intelligent Translation 的收缩原则

本轮确认，这个副本的重点不是“能不能直接给外部安装运行”，而是：

1. 能否看出它已经被做成一个稳定可跑的 Demo
2. 能否看出它在成本、稳定性、格式保护和复用性之间做过清楚取舍
3. 能否看出它具备进一步产品化的思路

因此本轮做了两件事：

1. 合并双入口，只保留一个统一的 `README.md`
2. 明确这个项目的证据中心是白皮书、审计、复盘和核心源码，而不是原始 Session

这里也同步确认：

- 这个项目的原始对话记录不完整
- 所以它不负责证明“最早的真实思路链”
- 它更适合证明“已经做出来、已经稳定、已经考虑过推行方式”
- 如果要分析作者本人更原始的一手材料，应把重心放在 `Solution Diagram Workflow` 的 `transcripts/` 上，而不是放在这个项目上

## 4. 两个项目之间的差异化强调

本轮明确不把两个项目都包装成同一种叙事。

差异化表达如下：

1. `Solution Diagram Workflow` 重点展示探索、收口、Skill 化和验证思维
2. `Excel Intelligent Translation` 重点展示完整度、稳定性、成本意识和产品化推进思路

共同点可以被看见，但不需要在两个入口里同时被高强度重复强调。

## 5. 本轮验收结果

本轮完成标准如下：

1. `Solution Diagram Workflow` 的入口已经围绕最终 Skill 重写
2. `Solution Diagram Workflow` 中旧输出和重复结构已从展示主路径移出
3. `Excel Intelligent Translation` 不再保留双 `README`
4. 两个副本的入口都已经改成“怎么读、看什么、边界是什么”的导向方式
