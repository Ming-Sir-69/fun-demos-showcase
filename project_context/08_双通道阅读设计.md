# 双通道阅读设计

## 1. 设计原则

同一套文件不能强行用同一种顺序服务所有读者。

因此本项目正式采用双通道阅读设计：

1. 人类短路径
2. AI 证据路径

## 2. 人类短路径

### 目标

让人类读者用尽量少的时间，完成第一轮经验判断和岗位匹配判断。

### 适合判断的问题

1. 这个大项目值不值得继续看
2. 为什么选这两个项目
3. 这两个项目分别体现了什么能力
4. 是否体现了 AI 产品经理所需的产品判断、技术路径选择和推进意识

### 推荐路径

1. 大项目根目录 `README.md`
2. `selected_projects/README.md`
3. `01_solution_diagram_workflow/README.md`
4. `02_excel_intelligent_translation/README.md`
5. 再根据兴趣跳转到少量关键 `project_context/` 文件

### 允收标准

只要做到以下程度，即可视为人类侧可允收：

1. 读者在 3 分钟内知道先看什么
2. 读者在 5 分钟内知道两个小项目各自的展示重点
3. 不需要先读长文本 `transcripts/` 才能完成第一轮判断

## 3. AI 证据路径

### 目标

让 AI 基于多文件与长上下文，完成较为客观和结构化的分析。

### 适合判断的问题

1. 多文件项目架构关系是什么
2. 长对话中真实出现过哪些决策拐点
3. 两个项目分别证明了哪些能力
4. 求职者画像可以从哪些原始证据中提取

### 推荐路径

1. 大项目根目录 `README.md`
2. `selected_projects/README.md`
3. `01_solution_diagram_workflow/README.md`
4. `01_solution_diagram_workflow/project_context/`
5. `01_solution_diagram_workflow/transcripts/`
6. `02_excel_intelligent_translation/README.md`
7. `02_excel_intelligent_translation/project_context/`
8. `02_excel_intelligent_translation/src/`

### 允收标准

只要做到以下程度，即可视为 AI 侧可允收：

1. AI 能明确区分入口层、证据层、长文本层
2. AI 能明确知道 `Solution` 的 `transcripts/` 是作者一手材料核心入口
3. AI 能明确知道 `Excel` 更适合承担完整度、稳定性和产品化能力证据

## 4. 两个项目在双通道中的角色分工

### Solution Diagram Workflow

更适合承担：

1. 探索路径
2. 决策拐点
3. Skill 化收口
4. 原始长对话证据
5. 作者一手工作材料

### Excel Intelligent Translation

更适合承担：

1. 已跑通 Demo
2. 稳定性与成本意识
3. 产品化推进思路
4. 架构演进与复盘

## 5. 当前允收结论

当前这一层设计已经达到可允收状态。

依据：

1. 顶层入口中已经明确区分“给人读”和“给 AI 读”
2. 两条路径都可以在一屏左右说清
3. 两条路径之间没有角色混淆
